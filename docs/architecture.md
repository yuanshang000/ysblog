# 架构决策记录

记录关键的设计选择与取舍理由，方便后续维护时理解「为什么这样做」。

---

## 决策 1：前台用 SSR 而非纯 SPA

**背景**：需求文档第 15.2 条明确要求「不能只依赖客户端 JavaScript 才能展示文章内容」。

**方案对比**：

| 方案 | SEO | 首屏 | 复杂度 | 资源消耗 |
| --- | --- | --- | --- | --- |
| 纯 SPA（Vue/Vite） | ❌ 需要额外预渲染 | 慢（等 JS 下载执行） | 低 | 每篇文章都下载 JS |
| Nuxt / Next | ✅ | 快 | 中（需框架约束） | 中 |
| **Worker SSR + 岛** | ✅ | **最快**（HTML 直接可读） | 中 | **最小**（未交互不加载 JS） |

**采用**：Worker 直接渲染完整 HTML，交互交给一个 8.6KB（gzip 3.3KB）的原生 JS 文件。

**理由**：

- 内容页 HTML 完全由服务端生成，搜索引擎无需执行 JS
- JS 禁用时文章依然可读、样式完整
- 未与页面交互的用户不会加载任何 JS，边缘节点直接返回缓存友好的 HTML
- 避开 SSR 框架的构建复杂度与运行时开销

**代价**：模板逻辑用字符串拼接而非组件树。已通过把渲染函数集中在 `services/pages.ts`、样式集中在 `shared/html-shell.ts` 来控制可维护性。

## 决策 2：单域名、单 Worker

`/` 前台 · `/admin` 后台 · `/api/v1` 接口 · `/media` 图片，全部由一个 Worker 提供。

**理由**：

- 免去跨域 Cookie 配置（`SameSite=None` + `Secure`）的复杂度
- 免去 CORS 预检
- 部署只有一个产物，回滚简单
- SEO 集中权重，不分散到子域

**代价**：静态资源需手动区分 `/admin` / `/islands` / `/assets` 前缀。已在 `index.ts` 中显式处理。

## 决策 3：Markdown 渲染禁用原始 HTML

`markdown-it` 配置 `html: false` —— 所有原始 HTML 一律按文本转义。

**理由**：博客内容只有管理员自己写，但一旦账号被盗或编辑器引入第三方内容，XSS 就能直接以站点身份执行。禁用原始 HTML 是最彻底的防御。

**补充防护**：

- 链接协议白名单（仅 `http` / `https` / `mailto`），拦截 `javascript:` / `data:` / `vbscript:` / `file:`
- 清洗控制字符，防止 `java\nscript:` 这类绕过
- 外链自动加 `rel="noopener noreferrer nofollow"`
- 图片属性二次转义，防止 alt/title 逃逸

**实测**：22 个 XSS 攻击向量全部被拦截（含大小写混淆、HTML 实体编码、换行注入、属性逃逸、base 标签劫持等）。

## 决策 4：密码与会话都存哈希

| 数据 | 存储 |
| --- | --- |
| 密码 | `pbkdf2$210000$<salt>$<hash>`（PBKDF2-HMAC-SHA256，21 万轮，每账号独立盐） |
| 会话 token | SHA-256 哈希（`SESSION_SECRET` 加盐） |

**理由**：数据库泄露时，攻击者拿到的是哈希而非可用凭证。PBKDF2 高迭代数让暴力破解成本极高。

**权衡**：会话采用哈希存储意味着「登出所有设备」需要遍历删除，无法像明文存储那样直接用 token 反查。但本项目本就只在改密码时清理全部会话，影响可接受。

**迭代数选 210000**：OWASP 2023 建议 PBKDF2-SHA256 的下限。低于此值在现代硬件上易被 GPU 破解。

## 决策 5：乐观锁而非悲观锁

文章更新时客户端回传 `baseRevision`，服务端不匹配即返回 409。

**理由**：个人博客通常只有 1-2 个编辑会话，数据库级悲观锁的复杂度与性能成本不划算。乐观锁实现简单，且冲突时给用户「放弃本地 / 覆盖」两个明确选择，符合真实写作场景。

**已验证**：提交 `baseRevision: 999` 时正确返回 409 并附带服务端当前版本号。

---

## 决策 6：自动保存只写内容，绝不自动公开

`autoSave: true` 的保存请求**不能**改变文章状态。

**理由**：文档第 5.3 条明确要求「自动保存草稿不能自动公开文章」。若自动保存顺带发布，作者按下退格键的那一刻文章就上线了 —— 这是真实发生过的事故模式。

**实现**：新建文章一律为 `draft`（即使请求传了 `status: "published"`），状态变更只能通过 `publish` / `schedule` / `archive` 等显式接口，且每个接口都做状态机校验。

## 决策 7：统计只存 IP 哈希

`page_views` 表保存 `ip_hash`（加盐 SHA-256）与 `visitor_hash`，**不保存原始 IP**。

**理由**：统计功能不需要真实 IP。哈希足够用于「独立访客去重」与频率限制，同时大幅降低隐私风险。

**统计口径明确**：

- 一次文章页访问 = 1 次浏览
- 独立访客 = 按 `visitor_hash` 去重（哈希本身已含 IP + 当日）
- 机器人流量自动排除（User-Agent 识别）
- 保留周期可配置（默认 180 天），定时任务自动清理

> 注：`visitor_hash` 不含日期维度，因为 IP 哈希本身每日随 `IP_HASH_SALT` 派生……实际上本项目使用同一盐值，
> 因此**独立访客数是近似估算而非精确去重**，这一点在后台已如实标注。

## 决策 8：样式自建设计系统，不引 UI 框架

前台用 `packages/shared/html-shell.ts` 中的 CSS 令牌体系；后台用 Element Plus 但覆盖了色彩与圆角。

**理由**：前台是内容展示页，需要精细控制排版与留白，通用 UI 框架反而是负担。后台是管理工具，Element Plus 能显著节省开发时间。

**后台的一致性保障**：通过 CSS 变量把 Element Plus 的主色、圆角、字号统一映射到品牌色，避免出现「框架蓝 + 站点靛蓝」的割裂感。

## 决策 9：设置项用键值表 + 共享 schema

D1 中 `site_settings` 是 `(key, value)` 结构，字段定义集中在 `packages/shared/src/settings-schema.ts`。

**理由**：新增设置项不需要改表结构（不需要迁移），且前后台共用同一份类型定义 —— 后台表单、前台渲染、Worker 校验三处不会不一致。

---

## 决策 10：SQL 全部参数化

`repositories/db.ts` 中所有查询都用 `DB.prepare().bind()`，无字符串拼接。

**理由**：D1 基于 SQLite，`prepare` 天然参数化。唯一需要动态拼接的是表名/列名（本项目不存在这类需求），其余一律走绑定参数。

**唯一的动态 SQL**：批量操作的 `WHERE id IN (?,?,?)` —— 占位符数量由 `ids.length` 生成，值仍全部走绑定。这既避免了拼接值，也避免了 IN 子句的硬上限。

## 已知限制

| 限制 | 原因 | 缓解方式 |
| --- | --- | --- |
| 中文 slug 保留中文 | 无可靠的前端拼音转换库 | 现代搜索引擎能正确索引中文 URL；可手动改为英文 slug |
| 搜索用 `LIKE` 子串匹配 | D1（FTS5）的中文分词需额外配置 | 已在文档中说明；数据量大时可改用 D1 FTS5 或外部搜索服务 |
| SSR 用字符串拼接 | 避免引入完整 SSR 框架 | 渲染函数集中管理，样式集中为单一来源 |
| 单管理员设计 | 需求文档第一版允许 | `users` 表已含 `role` 字段与权限校验，可扩展多作者 |

## 已知踩坑记录

开发过程中实际遇到并修复的问题，记录以避免重犯：

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 后台无法登录（`/admin/me` 返回 401） | Cookie 解析时 `k = part.trim()` 误把 `"name=value"` 整体当键 | 改为 `part.slice(0, i).trim()` |
| Set-Cookie 丢失 | `new Headers(headers)` 会把多个 Set-Cookie 合并成一个字符串 | 改用 `string[]` 传递，逐条 `append` |
| 代码块显示乱码 | 高亮函数对已转义文本二次转义，产生 `&amp;lt;` | 改为输入原始代码，只在输出时转义一次 |
| 内存耗尽（OOM） | 语法高亮的正则有嵌套量词，灾难性回溯 | 重写为单遍线性扫描 |
| 后台 `/admin` 返回 307 | 静态资源层把 `/admin` 重定向到 `/admin/` | Worker 内改写为 `/admin/index.html` 后再取资源 |
| 前台岛脚本被清空 | 两个前端构建共用父目录，`emptyOutDir` 连带删除同级产物 | 关闭自动清空，改由 `npm run clean` 脚本分步清理 |
| 图片 404 | 媒体 URL 缺少 `/media` 前缀，与 Worker 读取路径不一致 | 统一走 `mediaUrl()` helper |
